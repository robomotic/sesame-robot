# Plan: Convert Sesame Robot to ESP-NOW Protocol

## Overview

Convert the Sesame robot from WiFi/WebServer-based control to ESP-NOW protocol. Create a new ESP32-C3 controller (`ESP32_C3_Sesame`) that bridges a computer/Raspberry Pi (via USB serial) to the robot (via ESP-NOW).

**Robot board:** ESP32-S3  
**Controller board:** ESP32-C3 Mini  
**WiFi removal:** Complete (no compile-time option)  
**Serial CLI:** Kept on robot for debugging  

---

## Architecture

```
┌─────────────┐    USB Serial     ┌─────────────────┐    ESP-NOW     ┌──────────────┐
│  Computer/  │ ←──(text cmds)──→ │  ESP32-C3 Mini  │ ←──(binary)──→ │  ESP32-S3    │
│  Raspberry  │                   │  (Controller)   │               │  (Robot)     │
│  Pi         │                   │  ESP32_C3_Sesame│               │  8 Servos    │

└─────────────┘                   └─────────────────┘               │  (MPU6050*)  │
                                                                    └──────────────┘
                                                            * Future sensor integration
```

## ESP-NOW Binary Protocol

### Message Format (max 250 bytes)

```
[1 byte: msg_type] [1 byte: msg_id] [N bytes: payload]
```

- `msg_type`: Command/response type (see tables below)
- `msg_id`: Sequence number (0-255, wraps). Used to match responses to requests.
- `payload`: Type-specific data

### Command Messages (Controller → Robot)

| Type | Hex  | Name           | Payload                                      | Description                        |
|------|------|----------------|----------------------------------------------|------------------------------------|
| 0x01 | CMD  | MOTION_CMD     | Null-terminated string (max 16 chars)        | Play motion (e.g. "forward", "wave") |
| 0x02 | FACE | FACE_CMD       | Null-terminated string (max 20 chars)        | Set face (e.g. "happy", "idle")    |
| 0x03 | STOP | STOP_CMD       | (none)                                       | Stop current motion                |
| 0x04 | SSET | SERVO_SET      | `[uint8 channel, uint8 angle]` (2 bytes)     | Set single servo angle (0-180)     |
| 0x05 | SALL | SERVO_ALL      | `[uint8 angle]` (1 byte)                     | Set all servos to same angle       |
| 0x06 | TSET | TRIM_SET       | `[uint8 channel, int8 value]` (2 bytes)      | Set subtrim for one servo          |
| 0x07 | TGET | TRIM_GET       | (none)                                       | Request all subtrim values         |
| 0x08 | TRST | TRIM_RESET     | (none)                                       | Reset all subtrims to 0           |
| 0x09 | CSET | CONFIG_SET     | `[uint8 key, int16 value]` (3 bytes)         | Set a config parameter             |
| 0x0A | CGET | CONFIG_GET     | (none)                                       | Request all config values          |
| 0x0B | STAT | STATUS_GET     | (none)                                       | Request robot status               |
| 0x0C | PING | PING           | `[uint32 timestamp_us]` (4 bytes)            | Latency measurement                |

**Config keys for CONFIG_SET (0x09):**
- `0x01` = frameDelay
- `0x02` = walkCycles
- `0x03` = motorCurrentDelay
- `0x04` = faceFps

### Response Messages (Robot → Controller)

| Type | Hex  | Name           | Payload                                           | Description                     |
|------|------|----------------|---------------------------------------------------|---------------------------------|
| 0x80 | ACK  | ACK            | `[uint8 orig_msg_id, uint8 status]` (2 bytes)     | 0=OK, 1=ERR                    |
| 0x81 | TDAT | TRIM_DATA      | `[int8 × 8]` (8 bytes)                            | All subtrim values              |
| 0x82 | CDAT | CONFIG_DATA    | `[int16 × 4]` (8 bytes)                           | frameDelay, walkCycles, mcd, fps |
| 0x83 | SDAT | STATUS_DATA    | `[16 char cmd, 20 char face]` (36 bytes)           | Current command + face name     |
| 0x84 | PONG | PONG           | `[uint32 orig_timestamp, uint32 robot_time]` (8B)  | Ping response                   |
| 0x85 | SENS | SENSOR_DATA    | `[float ax, ay, az, uint32 ts]` (16 bytes)         | Future: MPU6050 data            |

### Shared Header File

Create `espnow-protocol.h` to be included by both Controller and Robot firmware, containing:
- All struct definitions
- Message type constants
- Common utilities

## Serial Protocol (Computer ↔ ESP32-C3)

Text-based, one command per line, `\n` terminated.

### Commands (Computer → Controller)

```
CMD <motion>           # e.g. CMD forward, CMD wave, CMD rest
STOP                   # Stop current motion
FACE <name>            # e.g. FACE happy, FACE idle
SERVO <ch> <angle>     # e.g. SERVO 0 90 (channel 0-7, angle 0-180)
SERVO_ALL <angle>      # Set all servos to angle
TRIM_SET <ch> <val>    # e.g. TRIM_SET 0 5 (channel 0-7, value -90..90)
TRIM_GET               # Request subtrim values
TRIM_RESET             # Reset all trims
CONFIG_SET <key> <val> # e.g. CONFIG_SET frameDelay 100
CONFIG_GET             # Request config values
STATUS                 # Request robot status
PING                   # Measure round-trip latency
MAC                    # Print controller's MAC address
CHANNEL <n>            # Set ESP-NOW channel (1-13)
```

### Responses (Controller → Computer)

```
OK                                              # Command acknowledged by robot
OK SENT                                         # Command sent (no ACK yet)
ERR <message>                                   # Error description
TRIM <v0> <v1> <v2> <v3> <v4> <v5> <v6> <v7>   # Subtrim values
CONFIG frameDelay=<n> walkCycles=<n> motorCurrentDelay=<n> faceFps=<n>
STATUS cmd=<motion> face=<name>
PONG rtt=<ms>                                   # Round-trip time
MAC <aa:bb:cc:dd:ee:ff>                         # Controller MAC address
SENSOR ax=<f> ay=<f> az=<f>                     # Future: MPU6050 data
```

## Implementation Details

### Robot Firmware (`sesame-firmware-espnow.ino`)

**Remove:**
- `#include <WiFi.h>`, `<WebServer.h>`, `<DNSServer.h>`, `<ESPmDNS.h>`
- `captive-portal.h` include
- All web server route handlers (`handleRoot`, `handleCommandWeb`, `handleGetSettings`, etc.)
- DNS server, mDNS, web server objects and logic
- `WebServer server(80)`, `DNSServer dnsServer`
- WiFi AP/STA configuration code
- WiFi info scrolling code (`updateWifiInfoScroll`, `showingWifiInfo`, `wifiScrollPos`, etc.)
- Network mode variables (`networkConnected`, `networkIP`, `deviceHostname`)

**Add:**
- `#include <esp_now.h>`, `<esp_wifi.h>`
- `#include "espnow-protocol.h"`
- ESP-NOW initialization in `setup()` (WiFi STA mode, set channel, init esp_now, register callbacks)
- `OnDataRecv()` callback: parse incoming messages by type, dispatch to handler functions
- `OnDataSent()` callback: track send success/failure
- Message handler functions:
  - `handleMotionCmd()` → sets `currentCommand`
  - `handleFaceCmd()` → calls `setFace()`
  - `handleStopCmd()` → clears `currentCommand`
  - `handleServoSet()` → calls `setServoAngle()`
  - `handleServoAll()` → sets all servos
  - `handleTrimSet()` → sets subtrim + applies + saves
  - `handleTrimGet()` → sends TRIM_DATA response
  - `handleTrimReset()` → resets all trims
  - `handleConfigSet()` → updates config + saves
  - `handleConfigGet()` → sends CONFIG_DATA response
  - `handleStatusGet()` → sends STATUS_DATA response
  - `handlePing()` → sends PONG response
- `sendEspNowResponse()` helper for sending responses back
- Controller MAC address configuration (`#define CONTROLLER_MAC`)

**Keep unchanged:**
- All servo control code (servoPins, setServoAngle, applySubtrimToCurrentPose)
- All face/display code (OLED, face animation, idle blink)
- All movement sequences (via `movement-sequences.h`)
- NVS storage (subtrim, settings)
- Serial CLI for debugging
- `loop()` structure (command dispatch, face updates, serial CLI)

**Modify in `loop()`:**
- Remove `dnsServer.processNextRequest()` and `server.handleClient()`
- Remove `updateWifiInfoScroll()`
- Keep `updateAnimatedFace()`, `updateIdleBlink()`, command dispatch, serial CLI

**Modify in `delayWithFace()`:**
- Remove `server.handleClient()` and `dnsServer.processNextRequest()`

**Modify in `pressingCheck()`:**
- Remove `server.handleClient()` and `dnsServer.processNextRequest()`

### Controller Firmware (`ESP32_C3_Sesame.ino`)

**Structure:**
```
setup():
  - Serial.begin(115200)
  - WiFi.mode(WIFI_STA)
  - Set WiFi channel
  - esp_now_init()
  - Register peer (robot MAC)
  - Register send/receive callbacks
  - Print MAC address and ready message

loop():
  - Check serial for incoming text commands
  - Parse and dispatch commands
  - Handle ESP-NOW response timeout (500ms default)

OnDataRecv():
  - Parse response message type
  - Format as text and print to serial

OnDataSent():
  - Track delivery status
```

**Serial parsing:**
- Read serial line-by-line into buffer
- Split on first space to get command verb + arguments
- Validate arguments, build ESP-NOW message struct, send

**Message ID tracking:**
- Increment `msg_id` counter per sent message
- Store last sent `msg_id` + timestamp for timeout detection
- Match incoming ACK `orig_msg_id` to pending request

## Future Considerations (Not Implemented Now)

- **MPU6050 integration**: The `SENSOR_DATA` (0x85) message type is reserved. A third ESP-NOW node (e.g. AtomS3) could send IMU data to the controller, which relays it to the computer. Or the robot itself could have an MPU6050 and periodically stream data.
- **OTA updates**: Could be re-enabled via WiFi when needed.
- **Multi-robot**: ESP-NOW supports multiple peers; the controller could manage multiple robots.
- **Bidirectional state sync**: Robot could push status changes (command completion, idle state) without being polled.
- **Python library**: A Python wrapper around the serial protocol for scripting robot behaviors from the RPi.

## Pin / Board Configuration Notes

**Robot (ESP32-S3):**
- ESP-NOW init uses `WiFi.mode(WIFI_STA)` + `esp_wifi_set_channel()`
- ESP-NOW callbacks use ESP32 core 3.x API: `esp_now_recv_info_t` for receive, `wifi_tx_info_t` for send
- I2C and servo pins unchanged from current firmware
- The ESP32-S3 needs the correct board selected in Arduino IDE (ESP32S3 Dev Module or equivalent)

**Controller (ESP32-C3):**
- Already tested with ESP-NOW in the existing `ESP32_C3_Controller.ino`
- USB CDC serial (native USB on C3) at 115200 baud
- No GPIO usage beyond ESP-NOW radio
